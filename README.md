# Astra Defect Tracker

Учебный прототип системы регистрации и сопровождения дефектов игрового проекта.

## Возможности

- регистрация и вход по HTTP Basic;
- проекты и карточки дефектов с версией игры, платформой, шагами воспроизведения, ожидаемым и фактическим результатом;
- фильтрация по состоянию и приоритету, поиск по заголовку и описанию;
- комментарии и история смены состояния;
- роли администратора, разработчика, тестировщика и заявителя;
- REST API и клиентская страница;
- миграции схемы PostgreSQL через Flyway.

## Запуск

1. Скопируйте `.env.example` в `.env` и замените локальные пароли.
2. Запустите `docker compose up --build`.
3. Откройте `http://localhost:8080`.
4. Для локальной демонстрации используйте администратора из `.env`. Обычный пользователь может зарегистрироваться на стартовой странице.

Для закрытия контейнеров выполните `docker compose down`. Данные PostgreSQL сохраняются в именованном томе. `docker compose down -v` удаляет том с учебными данными.

## API

Базовый адрес: `/api`. Справочник методов описан в `docs/openapi.yaml`.

Основные маршруты:

| Метод | Маршрут | Назначение |
|---|---|---|
| POST | `/api/auth/register` | регистрация пользователя с ролью REPORTER |
| GET | `/api/me` | текущий пользователь |
| GET | `/api/projects` | список проектов |
| POST | `/api/projects` | создание проекта для ADMIN |
| GET, POST | `/api/projects/{id}/issues` | список и регистрация дефектов |
| GET | `/api/issues/{id}` | карточка дефекта |
| PATCH | `/api/issues/{id}/status` | смена состояния для ADMIN, DEVELOPER, TESTER |
| PATCH | `/api/issues/{id}/assignee` | назначение ответственного для ADMIN, DEVELOPER |
| GET, POST | `/api/issues/{id}/comments` | обсуждение дефекта |
| GET | `/api/issues/{id}/history` | история состояния |

## Архитектура

Код разделён на доменную модель и правила, прикладные сценарии с портами, адаптеры PostgreSQL и HTTP-интерфейс. Направление зависимостей идёт к доменной модели. Схема данных и правила переходов находятся в `src/main/resources/db/migration` и `domain/IssueLifecycle`.

## Ограничения учебного прототипа

Вход использует HTTP Basic. Перед размещением вне локальной демонстрации необходимо включить TLS, заменить демонстрационные секреты, настроить резервное копирование и пересмотреть регистрацию пользователей и права доступа. Сервис не хранит бинарные вложения; в карточке предусмотрены текстовые диагностические поля.
